# Supply-chain: анализ зависимостей от поставщиков

Прототип задачи № 2 «Атака через поставщика» интенсива «Мыслить как хакер». Python и Neo4j хранят связи с источниками, проверяют условия сценария и формируют объяснимые отчёты.

В комплекте три реальных кейса — Лента, авиакомпания «Россия», Почта России — и отдельный синтетический пример резервирования. Исторические наблюдения отделены от результатов экспериментов. Исходные наборы со ссылками, датами и ограничениями находятся в [data](data).

## Скачать и запустить

Нужны работающий Docker Engine/Desktop и Docker Compose 2.24+. Python и Neo4j на компьютере устанавливать не требуется. Команды рассчитаны на Linux, macOS или WSL2 с доступом к Docker Desktop.

```sh
git clone https://github.com/GoDvOp/supply-chain.git
cd supply-chain
./start.sh
```

Без Git скачайте [ZIP репозитория](https://github.com/GoDvOp/supply-chain/archive/refs/heads/main.zip), распакуйте его целиком, откройте терминал в папке `supply-chain-main` и выполните:

```sh
sh start.sh
```

Первый запуск создаёт локальный `.env` со случайным паролем, собирает приложение, ждёт готовности Neo4j и выполняет демонстрации всех наборов. Для загрузки образов и зависимостей нужен интернет. После сборки анализ работает без сетевого сбора источников.

- Neo4j Browser: http://127.0.0.1:17474/
- Подключение в Browser: `bolt://127.0.0.1:17687`.
- Логин и пароль находятся в локальном `.env`; пароль в репозитории отсутствует.
- Отчёты и запросы создаются в `outputs/`, журнал демонстрации — `outputs/startup.log`.

Существующий `.env` сохраняется. Повторный импорт не дублирует исходный граф; новые расчёты получают отдельные паспорта `Run`. Данные Neo4j хранятся в постоянном томе Docker.

## Управление

```sh
./start.sh status
./start.sh logs
./start.sh test
./start.sh stop
```

`stop` останавливает стенд с сохранением данных. Скрипт можно вызвать из другой папки по полному пути. Если стандартные порты заняты, измените `NEO4J_HTTP_PORT` и `NEO4J_BOLT_PORT` в `.env`; после запуска скрипт выведет фактические адреса.

Для двух независимых копий используйте отдельные папки, разные порты и разные значения `COMPOSE_PROJECT_NAME` в их `.env`. По умолчанию имя проекта Compose — `lenta-supply-risk`; одно изменение портов не создаёт отдельный том базы.

Не меняйте пароль существующего тома простым редактированием `.env`. При ошибке подключения проверьте `status`, журнал Neo4j и соответствие пароля. Для резервной копии сохраните `.env` и данные тома; удаление тома уничтожает сохранённый граф.

## Посмотреть результаты

После `./start.sh` выполните в Neo4j Browser содержимое `outputs/compact_overview.cypher`: запрос показывает зависимости трёх компаний и компактные сводки `ImpactSummary`. Для сводок можно выбрать Caption → `name`. Подробный реестр наблюдений открывается запросом `outputs/observation_details.cypher`; оформление находится в `outputs/overview.grass`.

Примеры создаваемых отчётов:

| Файл в `outputs/` | Содержание |
|---|---|
| `S1_evidence.md` — `S4_evidence.md` | Условия сценариев Ленты по имеющимся сведениям |
| `compare_edi_bypass.md` | Сравнение обработки EDI до и после обхода |
| `sensitivity.md` | Все 27 комбинаций параметров очереди |
| `rossiya_historical.md` | Исторические последствия отказа Леонардо |
| `pochta_historical.md` | Сообщения о раскрытии сведений и ответных действиях |
| `compare_pochta_access.md` | Контрфактическое сравнение с отзывом доступа |

Рядом с Markdown сохраняются полные JSON. Эти файлы создаются программой и не включаются в Git.

## CLI

После первого запуска команды выполняются через `./start.sh cli`. Список доступен через `--help`. Для отчётов `--output` задаёт префикс файлов `.json` и `.md`.

```sh
./start.sh cli validate data/lenta.v1.json
./start.sh cli list --dataset rossiya --version 1 --kind observations
./start.sh cli assess --dataset lenta --version 1 --scenario S3 --mode evidence --output outputs/edi_evidence
./start.sh cli assess --dataset lenta --version 1 --scenario S3 --mode experiment --params experiments/edi_base.json --output outputs/edi_experiment
./start.sh cli compare --dataset lenta --version 1 --scenario S3 --before experiments/edi_base.json --after experiments/edi_bypass.json --output outputs/bypass
./start.sh cli overview --dataset rossiya --version 1 --output outputs/rossiya_overview
```

Также доступны `import`, `sensitivity` и `export`. Экспорт набора сохраняет полный снимок и схему Mermaid:

```sh
./start.sh cli export --dataset lenta --version 1 --output outputs/lenta.export.json
./start.sh cli validate outputs/lenta.export.json
```

Режим `evidence` сохраняет неизвестные условия; режим `experiment` принимает явно отмеченные допущения из `experiments/`. У набора есть `dataset_id`, версия и SHA-256. Изменение уже импортированной версии другим содержимым отклоняется. Исторические поля читаются из версионного снимка; карточка узла идентичности в Browser не заменяет его.

## Проверки и состав

Полный набор тестов на настоящей Neo4j:

```sh
./start.sh test
```

Критерии и соответствующие проверки перечислены в [таблице приёмки](docs/acceptance.md). Журналы — [verification.txt](docs/verification.txt) и [launcher-verification.txt](docs/launcher-verification.txt). При проверке без `RUN_NEO4J_TESTS=1` тесты, требующие базы, пропускаются.

При последней проверке чистой копии прошли **87 тестов**, первый и повторный запуск, остановка и восстановление с сохранением базы и пароля. Машинный [протокол проверки](docs/release-checks.json) содержит результаты и контрольную сумму файлов выполнения.

`src/supply_risk/` содержит ядро и CLI; `data/` — исходные наборы; `experiments/` — параметры экспериментов; `migrations/` — ограничения графа; `scripts/` — настройку и демонстрации; `tests/` — автоматические проверки. Зависимости закреплены в `requirements.lock`, Docker-образы — по digest. `.env.example` содержит шаблон без секрета.

## Ограничения

Граф и правила подготовлены по открытым материалам и не подтверждают нынешнее состояние систем. Очередь EDI описывает поток сообщений при заданных допущениях; экспериментальные числа и пороги не являются реальными показателями Ленты. Для других процессов нужна подходящая модель последствий. Отсутствие пути означает, что он не найден в данном наборе. Проект не рассчитывает вероятность атаки или денежные потери; независимая проверка прогнозной точности не проводилась. Активные действия против исследуемых организаций не выполнялись.

## Использование ИИ

ИИ использовался при разработке значительной части кода, тестов и документации, поиске и разборе публичных источников. Проверки опирались на исходные публикации, схемы данных, воспроизводимые примеры и автоматические тесты. Это не независимая экспертиза компаний. Во время сценарных расчётов LLM не вызывается.

# Приёмка по ТЗ 1.1

Автоматические проверки находятся в `tests/test_acceptance.py`; дополнительные пограничные случаи — в `tests/test_edges.py`. Интеграционные проверки запускаются с `RUN_NEO4J_TESTS=1` на живой Neo4j.

| Критерий | Проверка |
|---|---|
| T01 | Повторный импорт, неизменность числа узлов/ребер и данных |
| T02 | Неверная ссылка: нет частичного снимка; дополнительно проверен откат транзакции после записи |
| T03 | Доступ unknown/false/true даёт conditional/blocked/applicable_in_scenario |
| T04 | IMPLEMENTED не превращается в действующий доступ |
| T05 | EDI 800 сообщений, 4 ч, всего 12 ч |
| T06 | Обход 40: 480 сообщений, 2,4 ч, всего 10,4 ч |
| T07 | mu_r=lambda: очередь сохраняется; mu_r<lambda: растёт; null вместо бесконечности |
| T08 | Нулевой сбой / достаточный обход: Q=0 и T_clear=0 |
| T09 | Отрицательные, строки, bool, NaN и Infinity отклоняются |
| T10 | Два пути общей зависимости, один процесс и один расчёт |
| T11 | Нет повторов узлов при цикле; границы max_depth/max_paths помечены |
| T12 | Локальный отказ оставляет резерв; общий отказ затрагивает оба пути |
| T13 | Evidence сохраняет unknown; experiment сохраняет переопределения, исходный набор неизменен |
| T14 | Уточнение true/false воспроизводимо, P1 для пути к тяжёлым последствиям |
| T15 | Все 27 комбинаций, 12 non_draining; конечные агрегаты считаются отдельно |
| T16 | Изоляция двух наборов в одной базе |
| T17 | Экспорт, удаление тестового набора, восстановление, совпадение содержательного результата и input_hash |
| T18 | При неизвестном пороге числа есть, тяжесть не выдумывается |

Также проверяются неизменяемость версии и сосуществование версий 1/2, актуальность/конфликт утверждений, ошибки CLI и коды завершения, запрет гипотетического порога в evidence, сравнение отзыва доступа/ограничения прав/отказа от установки обновления, все четыре evidence-сценария, текст отсутствия пути и форматирование отчётов.

Полный демонстрационный прогон выполняется `scripts/demo.py` через CLI. Его отчёты находятся в `outputs/`. Результат последнего полного запуска тестов и чистого развёртывания записывается в `docs/verification.txt`.

В версии 1.0.1 добавлены регрессионные проверки в `tests/test_completion.py`: приоритет уточнения для независимых процессов разной тяжести, других неизвестных и параллельных утверждений; сохранение события, источников, паспорта, допущений каждой строки и предупреждений в sensitivity. Отдельная интеграционная проверка CLI воспроизводит усечение поиска до одного перехода и проверяет оба выходных формата. Также проверяется стабильность Markdown после канонического JSON-сохранения для assess, compare и sensitivity: порядок ключей не меняет читаемый отчёт.

Версия 1.1.0: `tests/test_historical_cases.py` проверяет два новых набора, 21 индивидуальную задержку, сохранение исторических наблюдений в экспериментах и при отсутствии пути, запрет очереди EDI для авиационного кейса, неизвестный объём раскрытия и подрядчика, валидацию Observation. Интеграционные проверки проверяют рёбра доказательств в Neo4j, повторный импорт и восстановление снимка с совпадением результата.

Версия приложения 1.1.1 добавляет `start.sh`: начальная настройка без Python на хосте, готовность базы, демонстрации и отчёты одной командой. `tests/test_launcher.py` проверяет сохранение конфигурации, фактические порты, запуск из пути с пробелами и передачу ошибок. Проверка чистого запуска, повторного старта и сохранения тома после stop/start записывается в `docs/launcher-verification.txt`. Версии расчётной модели и правил остаются 1.1.0.

Приложение 1.2.0: `tests/test_overview.py` проверяет компактный граф, исходные наблюдения и хеши, неизвестные величины, разделение единиц и снимков, синтетическую пометку, источники и ограничения. Интеграционные проверки подтверждают обновление без дубликатов, изоляцию наборов/версий и неизменность результата assess после создания сводок. Версии расчётной модели и правил остаются 1.1.0; алгоритм обзора имеет собственную версию 1.0.0.

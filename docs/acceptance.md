# Приёмка по ТЗ 1.1

Автоматические проверки находятся в `tests/test_acceptance.py`; дополнительные пограничные случаи — в `tests/test_edges.py`. Интеграционные проверки запускаются с `RUN_NEO4J_TESTS=1` на живой Neo4j.

| Критерий | Проверка |
|---|---|
| T01 | Повторный импорт, неизменность числа узлов/ребер и данных |
| T02 | Неверная ссылка: нет частичного снимка; дополнительно проверен откат транзакции после записи |
| T03 | Доступ unknown/false/true даёт conditional/blocked/applicable_in_scenario |
| T04 | IMPLEMENTED не превращается в действующий доступ |
| T05 | EDI 800 сообщений, 4 ч, всего 12 ч |
| T06 | Обход 40: 480 сообщений, 2,4 ч, всего 10,4 ч |
| T07 | mu_r=lambda: очередь сохраняется; mu_r<lambda: растёт; null вместо бесконечности |
| T08 | Нулевой сбой / достаточный обход: Q=0 и T_clear=0 |
| T09 | Отрицательные, строки, bool, NaN и Infinity отклоняются |
| T10 | Два пути общей зависимости, один процесс и один расчёт |
| T11 | Нет повторов узлов при цикле; границы max_depth/max_paths помечены |
| T12 | Локальный отказ оставляет резерв; общий отказ затрагивает оба пути |
| T13 | Evidence сохраняет unknown; experiment сохраняет переопределения, исходный набор неизменен |
| T14 | Уточнение true/false воспроизводимо, P1 для пути к тяжёлым последствиям |
| T15 | Все 27 комбинаций, 12 non_draining; конечные агрегаты считаются отдельно |
| T16 | Изоляция двух наборов в одной базе |
| T17 | Экспорт, удаление тестового набора, восстановление, совпадение содержательного результата и input_hash |
| T18 | При неизвестном пороге числа есть, тяжесть не выдумывается |

Дополнительные проверки:

| Файл | Что проверяет |
|---|---|
| `tests/test_acceptance.py`, `tests/test_edges.py` | Версии наборов, актуальность и конфликты утверждений, ошибки CLI, сценарные ограничения и форматирование отчётов |
| `tests/test_completion.py` | Приоритет уточнения условий, полноту данных sensitivity, усечение поиска и стабильность Markdown после сохранения JSON |
| `tests/test_historical_cases.py` | Исторические наблюдения, 21 индивидуальную задержку, неизвестный объём раскрытия и подрядчика, доказательства в Neo4j и восстановление снимков |
| `tests/test_launcher.py` | Сохранение конфигурации, фактические порты, пути с пробелами и передачу ошибок запуска |
| `tests/test_overview.py` | Компактный граф, источники, неизвестные величины, единицы измерения, изоляцию наборов и отсутствие влияния сводок на расчёты |

Полный запуск с Neo4j: `./start.sh test`. Демонстрации всех наборов выполняет `scripts/demo.py`; отчёты создаются в `outputs/`.

Протокол чистого развёртывания: [release-checks.json](release-checks.json). Журналы тестов и первого/повторного запуска: [verification.txt](verification.txt), [launcher-verification.txt](launcher-verification.txt).
